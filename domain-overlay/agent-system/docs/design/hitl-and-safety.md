## 目标与边界

- HITL 目标：让高风险、不确定、不可逆或高成本动作在自动执行前进入人工确认或人工接管。
- Safety 目标：防止越权工具调用、prompt injection、敏感数据泄露、错误记忆写入和不可控循环。
- 非目标：不替代业务审批制度、合规审查或生产发布流程；不把前端隐藏 / 禁用当作权限边界。

## 风险分级

| 风险级别 | 判断标准 | 默认处理 |
|---|---|---|
| 低 | 只读、无副作用、可公开信息 | 自动执行并记录 |
| 中 | 有副作用但可逆、影响范围有限 | 记录 + 可选人工确认 |
| 高 | 不可逆、花钱、删改数据、对外写入、影响客户或权限 | 必须人工确认或沙箱 |
| 禁止 | 触碰密钥、越权访问、绕过确认、违反项目边界 | 拒绝 + 记录 + 告警 |

## HITL Gate

要求：
- 高风险工具调用前必须展示目标、参数摘要、影响范围和回滚方式。
- 人工拒绝后不得换路径绕过确认。
- 人工修改参数后，应记录修改前后差异和执行结果。

## 人工接管与回滚

- 接管触发：连续失败、权限不明、越权风险、外部依赖异常、用户明确要求人工处理。
- 接管方式：暂停自动执行，输出当前 trace、已完成步骤、待处理步骤和建议选项。
- 回滚方式：列出可自动回滚、需人工回滚、不可回滚三类动作。

## Prompt Injection 防护

| 风险 | 检测信号 | 处理 |
|---|---|---|
| 指令覆盖 | 输入要求忽略系统 / 项目规则 | 拒绝覆盖，按项目规则执行 |
| 工具越权 | 请求未授权工具、路径、账号或外部写入 | 拒绝 + 记录到 trace |
| 数据外带 | 请求输出密钥、隐私、客户数据或内部策略 | 脱敏 / 拒答 / 人工确认 |
| 伪造上下文 | 输入声称已有授权但无法由项目事实验证 | 要求可审计依据 |

## 数据泄露与最小化

- 进入模型、工具、memory、trace 的数据都应最小化。
- 敏感字段需脱敏、摘要化或拒绝处理。
- 不确定是否敏感时，按高风险处理并进入人工确认。
